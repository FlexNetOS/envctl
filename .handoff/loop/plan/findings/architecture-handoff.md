## Gaps (architecture)

- **G1 — Portability is not in the crate graph.** Standalone-ization of the kernel depends on a CI clone step (`hf/Cargo.toml:45-47`), not a vendored/published/path-optional dependency. A union at `$META_ROOT + handoff` has no provable standalone build today. (vs trends baseline: pure-Rust no-C kernels are expected to `cargo build` from a clean clone.)
- **G2 — Contract duplicated across the union boundary.** `handoff.task.v1` exists as the schemars source-of-truth in handoff's `work-order` AND as a hand-mirrored copy in rusty-idd's `work-order`; drift is possible and uncaught (the exact fail-open class `validate_card` was built to kill, but only *within* handoff).
- **G3 — Two stale forks in one workspace.** `crates/{core,cli}` are 33–40% diverged from rusty-idd's superset; keeping both copies in the union doubles maintenance and invites a second prior-poor-merge.
- **G4 — The benign v1/v2 ambiguity is undocumented and untested.** The cfg-gating that keeps exactly one `Ledger` public is correct but implicit; a future feature edit (e.g. enabling `redb-store` while also `v2` re-export) could reintroduce a real `ambiguous_glob_reexports` error with no guard.
- **G5 — Tooling blind spot.** git-kb's name resolver fabricates SCCs and dead-code from same-name modules + clap dispatch; the graph is reliable for the Cargo DAG but not for call-cycle / dead-code conclusions without manifest cross-check.
