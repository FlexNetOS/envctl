## CLAIM rows

- **CLAIM[gov-001]** axis: governance+settings+config | surface: `.handoff/hooks/hooks.toml` ↔ `.claude/settings.json` | evidence: `.handoff/hooks/hooks.toml:12-116` declares the **14-event** typed contract incl. five **`fail_mode="block"`** hard gates (`TaskClaim:22-24`, `PreEdit:28-30`, `PreHandoff:38-42`, `PreSessionStart:59-62`, `PostTest:103-108`), but `.claude/settings.json:3-34` wires **only `SessionStart` + `SessionEnd`**, both via shell scripts, with **no `PreToolUse`/`PostToolUse`** key at all. The block gates are fired only by `hf hook run <event>` internally — there is **no bridge from the Claude Code edit/command lifecycle to `hf policy check-edit`/`check-claim`/`drift`**. confidence: High | impact: a Claude session can edit out-of-scope files or hand off with drift without ever tripping the block gate (enforcement depends on the agent *voluntarily* invoking `hf`) — the fail-OPEN class the kernel's own L7 law bans (`AGENTS.md:73-95`).

- **CLAIM[gov-002]** axis: governance+settings+config | surface: `.claude/agent-guard.toml` ↔ `.claude/settings.json` ↔ `.claude/rules/meta-destructive-commands.md` | evidence: `agent-guard.toml:16-106` defines 8 destructive-command patterns (force-push, reset --hard, clean -fd, checkout ., branch -D, stash drop/clear, rm -rf dangerous paths) and `meta-destructive-commands.md` ("Blocked by agent guard") promises they are blocked — but `.claude/settings.json:1-45` contains **no `PreToolUse` hook** invoking the guard.
